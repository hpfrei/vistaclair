Because of that split, APP.md is **kept 100% accurate** and stays small enough that keeping it accurate is realistic: every session updates it after any change to the app's *shape* (architecture, routing, invariants, files, dependencies, state) — but a change that only touches a function body usually needs **no doc update at all**. That is what makes the trust contract real: **reading APP.md and its `APP_<TOPIC>.md` detail files is as reliable as reading the source for everything they claim** — architecture, where-to-change, invariants, rationale. For the *exact current bytes* of a function you're about to edit, you still open that function in the source.

**Cells are pointers, not prose.** In the "Where to change what" routing table, the "Open" cell is a list of `symbol → file` pairs and nothing else — no sentence explaining what the symbol does, no CSS class names, no parameter lists, no behaviour notes. A cell that grows past roughly one line is a section trying to live in the table; move that detail into the named symbol's source or an `APP_<TOPIC>.md` and leave only the pointer. The same one-line rule governs the `## Files` and `## Routes & Functions` entries.

**Concrete budget**: aim for a root of **~6,000 tokens (~24 KB)**; treat **~8,000 tokens** as a hard ceiling. Past the ceiling the map is taxing every future session and must be compacted — move deep detail into `APP_<TOPIC>.md` files, collapse routing-table cells to pointers, and cut file/function entries to one line each. These are rough targets (≈4 chars/token), not a precise count. **Relocate, never delete** an invariant or gotcha when compacting.
