The model this tab asks for, passed as --model when it starts. Takes effect the next time the tab respawns — a running session cannot be moved between models. Leave on "Default" to pick up whatever the tab-strip cog (⚙) is set to at the next spawn.

A separate layer from the setting above: the model chosen there is what the CLI asks for, while this remaps it on the way through the proxy. Map incoming Claude model families to any configured model. Applied per-request before global proxy rules (e.g. the Model Override rule). Leave as "Default" to pass through unchanged. Skills are Markdown playbooks (.claude/skills/<name>/SKILL.md) with YAML frontmatter. Invoked by typing /name or auto-invoked when Claude matches the description. $ARGUMENTS substitutes user input. context: fork runs in an isolated sub-agent. Frontmatter controls model, effort, allowed-tools, hooks, and invocation visibility.
Custom skills in .claude/skills/
Built-in Skills Reference
Agents are sub-agent definitions in .claude/agents/<name>.md — YAML frontmatter + Markdown body (becomes the system prompt). Each invocation gets a fresh context window; only a summary returns to the parent. Delegated via the Agent tool, @mention, or claude --agent name. background: true runs concurrently. Agents cannot nest. Built-in: Explore, Plan, General-purpose.
Custom agents stored in .claude/agents/
Lifecycle hooks in .claude/settings.local.json
Hooks fire automatically at lifecycle points — executed by the harness, not by Claude. Live in settings.json (user / project / local scope).

Handler types: command (shell, JSON on stdin, exit 0 = allow / 2 = block), prompt (single-turn LLM eval), agent (sub-agent with Read/Grep/Glob). Synchronous by default; set async: true for fire-and-forget.

JSON output can block tools, modify inputs, inject context, or halt Claude.
PreToolUse → Tool Executes → PostToolUse → Claude Responds → Stop
Notification — Fires on notification events SubagentStop — Fires when sub-agent completes
PreToolUse hook Runs before a tool executes — can block or modify ▶

Description

Fires before any tool call. Can approve, block, or modify it based on exit code and stdout.

Environment Variables

VariableDescription
CLAUDE_TOOL_NAMETool name (e.g. Bash, Write)
CLAUDE_TOOL_INPUTJSON string of tool input
CLAUDE_SESSION_IDSession identifier

Exit Codes

  • 0 — Allow (stdout shown to Claude as context)
  • 2 — Block (stdout is the reason)
  • Other — Hook error; tool proceeds with warning

Use Cases

  • Prevent writes to protected files
  • Enforce naming conventions
  • Gate destructive Bash commands
  • Audit logging
PostToolUse hook Runs after a tool completes — react to results ▶

Description

Fires after tool completion. Stdout is injected as additional context for Claude.

Environment Variables

VariableDescription
CLAUDE_TOOL_NAMETool that was called
CLAUDE_TOOL_INPUTJSON input
CLAUDE_TOOL_OUTPUTJSON output/result

Use Cases

  • Auto-lint after writes
  • Auto-test after edits
  • Compliance logging
  • Validate code against standards

Stop hook Runs when Claude finishes responding — post-turn actions ▶

Description

Fires when Claude completes a turn. Stdout is fed back as a prompt — if it produces output, Claude processes another turn.

Environment Variables

VariableDescription
CLAUDE_STOP_REASONe.g. end_turn, max_tokens

Use Cases

  • Auto-run tests after coding
  • Change summaries
  • Trigger builds
  • Chain follow-up prompts
SubagentStop hook Runs when a sub-agent finishes its task ▶

Description

Fires when a sub-agent completes. Like Stop but scoped to sub-agents.

Use Cases

  • Validate sub-agent output
  • Log completions
  • Inject additional instructions
  • Quality gates
Configuration Reference
Three scopes: User (~/.claude/settings.json), Project (.claude/settings.json), Local (.claude/settings.local.json). Also definable in skill/agent frontmatter (scoped to lifetime).
Hook Object Schema config Structure of a hook entry in settings.json ▶ 
{
  "hooks": {
    "<HookType>": [
      {
        "matcher": "<ToolName>",   // optional: filter by tool
        "command": "<shell cmd>",   // required
        "timeout": 10000            // optional: ms
      }
    ]
  }
}

Fields

FieldTypeReqDescription
matcherstringoptTool name filter (PreToolUse/PostToolUse only). Omit for all tools.
commandstringreqShell command to execute
timeoutnumberoptTimeout in milliseconds

New Agent

Frontmatter reference

---
name: code-reviewer        # required
description: |             # required
  Reviews code for quality, security,
  and style.
model: sonnet              # sonnet/opus/haiku
tools: [Read, Grep, Glob, Bash]
disallowedTools: [Write, Edit]
maxTurns: 20
effort: high
background: false          # true = concurrent
isolation: worktree        # git worktree
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./validate.sh"
---

Fresh context per invocation. Only a summary returns to parent. Invoke via Agent tool, @mention, or claude --agent name.

New Hook

Handler types

# command — shell, JSON on stdin
# prompt  — single-turn LLM eval
# agent   — sub-agent with Read/Grep/Glob

Exit codes (command)

exit 0  # success, parse JSON stdout
exit 2  # block tool (PreToolUse)
other   # error, continue

JSON output (exit 0)

{
  "hookSpecificOutput": {
    "permissionDecision": "deny",
    "updatedInput": {"command": "..."},
    "additionalContext": "injected text"
  }
}

Examples

# Auto-format after writes:
jq -r '.tool_input.file_path' |
  { read -r f; prettier --write "$f"; }

# Block dangerous commands:
jq -r '.tool_input.command' |
  grep -q 'rm -rf' &&
  echo '{"decision":"block"}'

Matcher: regex on tool name. Omit or * to match all.
